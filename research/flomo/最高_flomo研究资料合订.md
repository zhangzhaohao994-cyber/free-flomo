# flomo 卖的究竟是什么

## 它在解决哪件事

**已核实披露**：产品主线是快速记录与回顾，不追求把长文档、任务、收藏和协作都包进去。输入、标签、检索、随机回顾和相关笔记形成一条个人知识使用链。[S01](https://flomoapp.com/)[S02](https://help.flomoapp.com/)

**分析判断**：用户真正购买的可能是“以后能用上自己的想法”的把握，而不只是云端字数。这个价值有时间延迟：第一天记录容易证明，半年后的决策帮助难证明。因此产品需要让新用户更快看到旧记录的意义，同时避免用即时 AI 反馈取代真实思考。

## 当前文档里值得注意的边界

记忆档案目前需至少 30 条笔记，且不会自动更新，需要重新生成。不能把“Agent 会记住对话”和“记忆档案持续自动更新”当成同一机制。[S06](https://help.flomoapp.com/ai/memory.html)

## 建议你实际体验的 6 个任务

这是待执行的体验计划，本次研究没有登录 flomo，也未购买会员或使用真实个人笔记测试。

1. 从手机到桌面各记一条，观察同步、离线与重复输入。
2. 记录 30 条原创测试笔记，包含同义词、时间变化和相互矛盾的观点。
3. 搜一个记过的主题，再搜完全没记过的事情，观察无证据时的反应。
4. 对一组笔记洞察，逐条打开引用，检查有没有把猜测写成事实。
5. 更正或删除一条重要记录，检查记忆、对话与导出是否同步改变。
6. 导出资料，核对文字、标签、图片和时间是否完整，再确认可以迁移到哪里。

**得到大脑**：它在“个人记忆”而不仅是语音输入上发生交集。面试可问：flomo 选择保留怎样的个人原始记录？把大量外部内容塞进来会改善记忆，还是稀释一个人真正关心的事？这是假设讨论，不能预设对方产品质量不好。[S42](https://doc.biji.com/)

**Obsidian / Memos**：共同代表数据可控和可自行维护的替代路径，但不能混为一家公司。面试可问：用户把数据导出后，为什么愿意持续付费回来？回答应落在可靠同步、使用习惯、检索质量或支持服务的可验证差别，而非只说“迁移成本高”。[S40](https://obsidian.md/pricing)[S44](https://github.com/usememos/memos)

**通用 AI 加现有笔记**：用户也可能导出笔记、交给通用模型、再粘回笔记，不购买专门记忆产品。这个替代路径已被 flomo 自己在 Agent 介绍中讨论。应比较步骤数、数据选择、更新、引用和纠错，而不只比较一次回答是否漂亮。[S04](https://help.flomoapp.com/ai/agent.html)

## 对标应该怎么测

准备同一批 30–100 条有授权的测试笔记，含日期、同义词、否定、观点变化和空白问题。比较：首次成功输入耗时、找到正确旧记录耗时、能否承认资料不足、引用支持度、纠错后旧结论是否失效、导出完整度，以及完成一次有效任务的真实成本。

不要以下载量、榜单、媒体热度或一个体验视频代替留存；也不要把“我更喜欢”写成“市场已经证明”。本次没有足够公开数据给各家市占率排位。

# 真正应该聊深的 6 个话题

## 开场不要先证明自己读了多少资料

建议从一个具体观察开始：“我注意到 flomo 从关联、洞察走到 Agent，但一直围绕个人记录。我的一个假设是，现在最难的不是生成答案，而是让用户信任答案确实来自自己的经历。我做了一个很小的验证，想听听你们现在最想解决哪一段。”

这是一种表达结构，需换成你真实做过的验证。没有做过就直接说这是待验证假设。不要把研究资料中的分析说成公司已经确认的问题。

## 第一优先：谁在什么场景里得到价值

**背景事实**：官方围绕记录与回顾，2026 访谈强调生产效率提高后仍需要挖掘用户价值。[S02](https://help.flomoapp.com/)[S20](https://www.sohu.com/a/1022656836_455313)

- 主问题：最近半年，你们最想服务好的那类用户，发生了什么变化？有没有一个具体使用现场改变了你们的判断？
- 深入：哪些记录或回顾行为最能预测续费？有没有人每天记，却从来不回看？你们如何理解这类用户？
- 再追问：如果用户说“我被洞察理解了”，如何区分短期情绪反馈与长期有用？
- 你可以展示：一页场景观察，含原问题、发生时刻、已有做法、付出的代价和反例。
- 听什么：对方能否举场景、区分人群和承认未知，而不只是给一个宏大用户画像。

## 第二优先：从洞察到 Agent 的决策变化

**背景事实**：历史年度回顾强调克制聊天界面，当前产品已提供 Agent。[S17](https://help.flomoapp.com/about-us/annual-letter-2025.html)[S04](https://help.flomoapp.com/ai/agent.html)

- 主问题：是哪条用户证据，让你们觉得对话现在值得做了？
- 深入：最初最大的顾虑是什么，现在还有哪部分没有解决？
- 再追问：判断 Agent 成功，首先看对话量、重新使用旧笔记、实际完成任务，还是 MAX 续费？这些指标冲突时如何取舍？
- 具体探针：如果某功能会增加对话时长，却不增加真实记录或回顾，你们会保留吗？什么证据能推翻直觉？
- 你可以展示：对同一份测试材料比较“只搜旧笔记”“总结”“对话追问”，解释哪个环节提供额外价值。

## 第三优先：个人记忆的准确、变化和遗忘

**背景事实**：记忆档案由笔记提炼，当前不会自动更新，洞察有来源标记。[S06](https://help.flomoapp.com/ai/memory.html)[S07](https://help.flomoapp.com/ai/insight.html)

- 主问题：用户改变了观点，怎样避免 AI 把旧偏好当作今天的事实？
- 深入：事实、用户当时的情绪、AI 的归纳会分层保存吗？能否追溯到原始笔记与时间？
- 再追问：更正或删除内容以后，画像、索引、对话记忆及已创建任务，分别如何处理？
- 具体探针：一条笔记写“我以前很讨厌跑步，现在喜欢了”，你们希望系统记住什么，如何判断答对？
- 你可以展示：30–50 条合成测试笔记，包含矛盾、过时、讽刺和无证据问题；提供失败样例而不仅是成功截图。
- 听什么：有无产品层面的可解释和纠错机制；不必要求对方披露系统提示词或用户私密数据。

## 第四优先：订阅和推理成本如何一起成立

**背景事实**：产品有分层订阅与扩展点数，官方说明峰时消耗存在变化。[S03](https://help.flomoapp.com/membership/pro.html)[S05](https://help.flomoapp.com/ai/agent-points.html)

- 主问题：做 MAX 时，最想让用户为哪件持续发生的价值付费？
- 深入：更关注升级率还是次年续费？PRO 的老用户会不会觉得原本属于自己的功能被移走？如何识别这种不满？
- 再追问：一次“有用的复盘”的模型、检索、语音与服务成本如何核算？重度用户怎样保护体验与毛利？
- 具体探针：如果模型成本翻倍，你们优先调模型、交互、额度还是价格？有没有一件绝不愿牺牲的体验？
- 听什么：是否承认成本与价格的取舍；能讨论口径和趋势即可，不把索要账本作为面试门槛。

## 第五优先：AI Builder 到底拥有多大决策权

**背景事实**：2026 访谈描述先跑 Demo、再写 PRD，并提到 Review、Debug 与职责协作的难点。[S20](https://www.sohu.com/a/1022656836_455313)

- 主问题：这个岗位入职前三个月，最希望消除哪一个具体问题？
- 深入：我负责验证到什么程度，能接触哪类脱敏数据，谁负责生产代码 Review 和上线？
- 再追问：当我的验证与创始人的判断不一致，用什么方式决定继续、搁置或停止？
- 具体探针：能否复盘最近一次没有上线的 Demo：谁提出、怎样否掉、投入如何评价？
- 听什么：会不会把“人人都能做”变成无人负责；岗位是否有结果定义、反馈和可支配资源。

## 第六优先：多产品与长期经营的资源分配

**背景事实**：公开经营组合含 flomo、幕布、小报童；历史有七年维护承诺。[S18](https://shaonan.blog/about/)[S10](https://help.flomoapp.com/about-us/about-us/company-concept.html)

- 主问题：未来一年团队最值得投入的是哪条业务、哪种用户价值？
- 深入：我进入哪个产品组、向谁汇报、和谁合作？跨产品工作是常态还是例外？
- 再追问：某业务短期增长慢时，保留投入的标准是什么？业务稳定与员工成长怎样同时实现？
- 听什么：是否能够区分服务维护、产品发展和岗位预算，而不是用长期愿景代替明确安排。

## 60 分钟怎么分配

| 时间 | 要完成的事 | 留下的证据 |
| --- | --- | --- |
| 0–5 分 | 介绍真实经历，确认对方当前关注点 | 一个可以展开的具体问题 |
| 5–20 分 | 展示一个自己验证过、含失败的案例 | 判断过程与证据，而非 Demo 数量 |
| 20–40 分 | 深入上面 2–3 个话题 | 具体场景、口径与分歧 |
| 40–52 分 | 岗位、协作、评估与资源 | 三个月目标和职责边界 |
| 52–60 分 | 双方补问，确认下一步 | 面试流程与待核事项 |

只剩十分钟，优先问：现在最痛的问题是什么；这个岗位前三个月如何判断有价值；意见分歧如何决策；服务哪条产品线；岗位预算与用工主体是什么。不要把所有尽调问题挤在第一轮。

## 可以问，但要选择时机

较早可问业务是否能覆盖投入、增长主要来源及主要成本；后期可问薪酬组成、奖金条件、试用期评价、办公与工时、社保主体、远程政策、保密与个人项目安排。对股权激励，需问清主体、归属和退出规则，不能把口头期权当现金工资。

## 讨论自建工具时的表达

如果带了自己做的笔记工具，说明为什么做、哪些环节亲测、哪些只是界面、哪些没有真实用户验证。能做出相似界面不等于理解云服务、支付、支持、长期可靠性和用户信任。适合拿来讨论“哪些东西容易复制、哪些真正要经营”，不要把复刻当成已证明超越官方产品。

## 根据岗位调整重点

| 设计 | 记录摩擦、信息架构、解释和纠错、跨端一致性 | 只展示静态美图 |

## 面谈后的判断

把对方的回答记成“原意摘要 / 我如何理解 / 下一步待验证”，经同意再记录原音。比较岗位目标是否清楚、是否能给真实案例、是否接受有证据的不同意见、承诺是否能落实到书面安排。没有回答某个商业秘密不等于有问题；反复回避岗位、工资和责任主体才值得继续核实。

# 带一份小而可证伪的作品

## 两天内可以完成的面试样本

选题：“旧笔记能否帮助用户纠正一个正在做的决定？”目标不是做完整第二大脑，而是从搜索结果里区分过去事实、当前观点和缺失信息。

### 原料与权限

准备 40 条自己原创的测试笔记，明确标为合成材料，不使用朋友聊天、医疗、公司机密或面试官的私密信息。构造 8 个题目：有答案、同义词、跨时间、观点改变、矛盾、无依据、恶意指令、删除后不可再用。

### 展示流程

1. 输入问题，展示检索到的原始卡片与日期。
2. 输出“有依据的结论 / 不确定的解释 / 需要再问的问题”。
3. 点击结论看到来源，允许指出错误。
4. 修改或删除原卡片，验证旧结论能失效。
5. 记录耗时、估算调用费与错误类型，不用漂亮回答掩盖失败。

### 验收表

| 指标 | 测什么 | 如何避免自证 |
| --- | --- | --- |
| 证据支持 | 每条结论能否由所引卡片支持 | 人工盲评，不由同一模型给自己打分 |
| 时间一致 | 会不会把过去的态度当现在 | 专门设置相反的前后记录 |
| 缺失处理 | 没有原料时能否承认不知道 | 提问材料里从未出现的事情 |
| 删除生效 | 用户删除后是否还出现在回答 | 复查索引、缓存、旧对话影响 |
| 成本与耗时 | 每次有效任务的资源消耗 | 记录失败与重试，不只报最佳值 |

这组实验用来显示判断方法，不足以代表真实 flomo 用户、线上质量或经营回报。

# 尽职调查，到底在查什么

## 这份研究属于哪一种尽调

它是基于公开资料的公司研究与求职准备。没有公司授权进入财务、银行、员工、人事和代码系统，也没有法律专业意见、实地访谈或审计。因此它能形成问题清单，不能出具“公司无风险”或“人员全部通过背调”的结论。

## 七个常被混用的词

| 名词 | 白话解释 | flomo 场景为什么要分清 |
| --- | --- | --- |
| 注册资本 | 公司登记中股东承诺出资的规模 | 100 万元注册资本不等于账上有 100 万元 [S31](https://m.zhipin.com/companys/866e83fb37b684d71nx62tq1.html) |
| 融资 | 通过股权、借款等取得资金；公开“轮次”通常指股权融资 | 零股权融资不排除股东垫资和借款 |
| 营收 | 按相应会计规则确认的经营收入 | 年费一次收款，服务却持续一年，收款与确认节奏可能不同 |
| GMV | 平台上的交易总额 | 小报童创作者成交不能全部记为平台收入 [S33](https://help.xiaobot.net/creator-legal.html) |
| 毛利 | 收入扣除直接提供服务的相应成本后剩余的部分 | AI 调用、云、存储、渠道成本如何归类要明确 |
| 净利润 | 再考虑人员、管理、税费等后的会计结果 | 有订阅进账不等于净赚同样金额 |
| 现金流 / 现金保障 | 实际资金进出与可用资金 | 七年基础维护承诺不等于完整团队七年工资 [S10](https://help.flomoapp.com/about-us/about-us/company-concept.html) |

以上是帮助理解的简化解释。具体会计分类、法律关系与税务处理，应查对应合同、账目与专业意见，不能仅据本资料作投资或签约决定。

## 值得了解的产品经营指标

| 指标 | 看什么 | 必须问的口径 |
| --- | --- | --- |
| 激活率 | 新用户有没有完成第一次有价值的动作 | “注册”“写一条”“写后回看”差别很大 |
| 留存率 | 同一批用户过一段时间是否继续使用 | 第 1 / 7 / 30 天或第 4 周，分母和窗口是什么 |
| 付费转化率 | 使用者中有多少人购买 | 是全体注册、活跃还是试用人群；是否含赠送 |
| 续费率 | 到期后有多少付费用户继续购买 | 到期当日、30 天内、自动扣费是否成功 |
| ARPU / ARPPU | 每个用户 / 每个付费用户贡献的收入 | 月或年、含税与退款、标价还是净实收 |
| CAC | 获得一个用户或付费用户的成本 | 现金投放之外，是否计人员、内容和优惠 |
| LTV | 一位客户生命周期可能贡献的价值 | 用收入还是贡献毛利，假设是否来自真实留存 |
| 单位贡献 | 一次服务或一位订阅者覆盖变动成本后还剩多少 | AI 重度用户与普通用户可能不同 |

**分析提示**：付费工具未必需要最高 DAU。关键是目标用户在重要场景里是否稳定获得价值，并愿意续费。不能用“每天不打开”单独判断其失败，也不能以此忽略流失。
